# theme-advice-skill 初期設計

スキル版：0.2.0 / 検討記録形式：1.0 / 共有JSON形式：1.0 / 設計日：2026-10-07

## 対象と到達点

藤村ゼミの3年生が、本人の経験から研究の問いを発想し、先行研究との差を調べ、4年次に確かめられる評価計画へ進む。メディアアートは新しい体験・表現と作品の完成度を重視する。

到達点は、学生が自分の言葉で説明できるテーマ提案書。採用や実施の決定は、学生と教員の相談で行う。AIの文章の完成度を、学生の理解や研究成果の代わりにしない。

## 実装の責務

| 部分 | 担うこと |
| --- | --- |
| `SKILL.md` | 対話の方針、段階の行き来、本人の判断、参照資料の使い分け |
| `references/` | ゼミ固有の指導、発想法、出典の扱い、評価の設計、記録の形式 |
| `assets/` | 再開用JSONと、教員に相談する提案書のテンプレート |
| `scripts/` | ファイル初期化、更新時の保全、参照ID等の機械的な整合性検査 |
| `scripts/share.py` | ニックネームの設定、共有JSONへのエクスポート、設定済みサイトへの明示的な送信 |
| `web/`, `api/`, `lib/` | 共有テーマの閲覧、投稿の認証・検証、Private Blobへの永続保存 |
| Codexの機能 | 会話、Web検索、ファイルの読み書き。スキルだけでは機能を追加しない |

テーマの相談・保存は外部サイトなしでも使える。共有時だけVercelの投稿APIを利用する。Python補助スクリプトは標準ライブラリのみで、テーマの提案や判定は行わない。設定・認証・モデルは既存のCodex環境を使い、特定モデルに固定しない。Cloud Shellでの起動は、ローカル導入済みの `npx codex` を使う。

## 段階と記録

| 段階 | 学生とAIが確かめること | 次へ進む目安 |
| --- | --- | --- |
| `explore` | 具体的な経験、関心、使える資源 | 本人が気になる場面を言える |
| `diverge` | 異分野・時代性・新技術からの異なる問い | 案への好み・違和感が分かる |
| `focus` | 候補の接点、RQの種、未確認事項 | 本人が調べたい候補を選べる |
| `investigate` | 最も近い研究、差、検索範囲、技術の利用条件 | 既知と未知の境界を説明できる |
| `plan` | 比較・観察、指標、データ、予備実験 | 問いを確かめる小さな計画がある |
| `proposal` | 本人の理由・説明と提案書 | 先生に相談する草案がある |

固定の質問票や、全員が同じ回数で進む設計にはしない。最初から案を持つ学生は途中から始められる。候補が既存研究と重なれば問いを修正したり、発想へ戻ったりする。

候補・資料に安定したIDを付ける。学生の判断、AIの提案、教員のコメントを分けて保存し、スナップショットで変更前を残す。出典を読む範囲、新規性の仮説、技術が使えるかの確認は別々に記録する。AIによる合計点・自動合否は作らない。

## 教育研究としての試行案

まず数人で、説明の分かりやすさ、質問への答えやすさ、保存・再開、提案書の相談への使いやすさを確かめる。これは運用を整える試行で、少人数の反応だけから教育効果を結論付けない。

研究として比較する場合の候補となる問い：

> 通常のAIへの自由な相談と比べて、このスキルを使う相談は、学生が自分の関心に基づくRQと評価計画を説明できるようになることに、どのような違いをもたらすか？

評価対象を、アイデアの数やAI文章の長さだけにしない。

| 観点 | 見る資料・行動 | 評価の注意点 |
| --- | --- | --- |
| 本人との接点 | 最初の関心、選択理由、短い口頭説明 | AIの代筆と、本人の説明を分ける |
| 問いの具体性 | 支援前の案と最終RQ | 対象・条件・観察する結果を教員が評価 |
| 研究の差の説明 | 近い先行研究、検索範囲、未確認事項 | 新しそうな題名だけで判定しない |
| 評価の成立 | 比較対象・指標・データ・予備実験 | RQに答える方法かを確認 |
| 主体的な修正 | 判断イベント、本人の説明、振り返り | AIの案を採用した数を主体性と同一視しない |
| 実行可能性 | 教員のコメントと予備実験 | 提案時の見込みと、実際の実行結果を分ける |

支援前の案と本人の説明を、最初の対話で可能な範囲で記録する。比較研究用の追加質問や時間計測は、研究実施の方法として別途決める。初期版の学生フローに研究用質問票を埋め込まない。

比較条件を作る場合は、同じ資料・時間・モデル・検索条件をなるべく揃える。学生の経験や元の案の違い、支援順序、同じ学生が先の支援から学ぶ影響を検討する。教員の評価には、条件を隠した資料や複数評価者を使えるかを検討する。人数・統計手法・対象期間は、予備試行を踏まえて決める。

共有する記録の範囲・収集への同意・保管方法は別の運用として決める。自由記述を含むため、仮名IDだけで匿名化できたとは扱わない。サイトには、本人が送信を依頼した共有テーマのみを投稿する。教育研究用の対話記録の自動収集は入れない。

## 検証の範囲

形式検査に加え、補助スクリプトで初期化・既存データの保全・不整合の検出・更新のバックアップを確認する。対話は架空の学生相談で、入口が未定の場合、検索が使えない場合、メディアアートの草案を求める場合を試す。検査は指導効果や実際の文献の網羅性を保証しない。

Cloud Shell上では、学生本人のアカウントで `/skills` での発見、Web検索、ホームディレクトリへの保存、次回の再開を確認する。現時点のローカル検査と、Cloud Shell実機の検証を分けて報告する。

2026-10-07に実施した初期検査：

- `skill-creator` の `quick_validate.py`：形式検査に合格。
- `python3 -m unittest discover -s tests -v`：23件に合格。既存記録の保持、スナップショット、新規性の根拠ID、本人の選択、インストール、ZIPバックアップ、更新失敗時の復元に加え、共有JSONの項目制限・ID保全・秘密設定・送信失敗時の扱いを確認。
- `npm test`：8件に合格。投稿・閲覧、同時投稿、再送、異なる内容で同じIDを送る場合の保全、認証、形式・サイズの拒否、保存先未設定、開発用の永続保存とページ取得を確認。
- 一時ディレクトリへの導入：開発用ファイルを含めず、導入先だけで記録を初期化できることを確認。
- 0.1.0の独立した対話試行：架空の学生相談3例を実施。関心未定の入口、検索不可時の候補整理、メディアアートの提案書草案で、保存・整合性確認・チェックポイントに成功。本人の発言とAIの案が区別され、新規性と技術の利用可能性は未確認として保持された。
- 導入済み0.2.0スキルからのHTTP検査：ローカルのサイトへ、架空の4テーマをJSONで保存・投稿・再送し、詳細の取得を確認。本人の検討記録が共有JSONに入らず、同じIDの再送が重複にならないことを確認。
- Chromeで一覧、ニックネーム検索、切り口による絞り込み、詳細・共有URLを確認。詳細からダウンロードしたJSONもスキーマに合格。390px幅でページ全体の横はみ出しがないことを確認。
- Vercel本番公開：`theme-advice.vercel.app` のビルド・デプロイ成功とReadyを確認。匿名のHTTPアクセスでトップ・Private Blobに接続した一覧・404・キーなしPOSTの401・設定したキーによる不正JSONの422を確認。架空の投稿はローカル検査のみに使用。

ローカル検査はmacOS上で実施。Google Cloud Shell実機、学生アカウントでの認証・検索、実際の学生に対する教育効果は未検証。架空の相談での成功は、すべての対話での同じ動作や新規性のあるテーマ創出を保証しない。

本番の正常な投稿・再送は、学生の最初の共有時に確認する。サーバーの保存・再送処理とPython送信はローカルで通して検査しているが、本番のBlobへの書き込みを架空のテーマで検査してはいない。

## 共有の設計

学生はCloud ShellのCodexで検討し、本人が選んだ候補を `theme.json` に書き出す。「テーマを送る」という依頼で、設定済みVercelサイトへPOSTする。サイトは読む・比較する場所とし、AIとの相談そのものはスキルで行う。

共有JSONはニックネーム・テーマ・関連資料を許可した形式で保存する。検討セッションから明示的に項目を抽出し、サイトでも同じJSON Schemaを検査する。関連資料は参照IDを保持し、ローカルパスを除く。出典の要約や興味との接点は本人が公開前に確認する。

閲覧はURLから可能、投稿はゼミ共通の送信キーを使う。ログインや教員コメント、個人別の投稿編集は初期版には含めない。ニックネームは本人確認を意味しない。新規性の調査段階と技術の利用可能性を別々に表示し、AIの点数で優劣を付けない。

投稿はUUIDごとの独立したJSONに保存し、共有インデックスの書き換えによる投稿消失を避ける。同じID・内容は再送成功として扱い、内容が違えば409で拒否する。内容を更新してエクスポートすると新しいIDになる。通信が切れた場合は成否未確認として記録し、同じJSONの再送で確認できる。

本番はPrivate Vercel Blobを必須にする。ストアに直接公開アクセスを与えず、API経由で共有テーマを読む。開発ではローカルディレクトリに保存するが、Vercel環境では利用を拒否する。導入・公開手順は [site-setup.md](site-setup.md) を参照。
