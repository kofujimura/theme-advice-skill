# 先行研究の確認と評価計画

## 新規性を調べる

候補の対象、条件、現象・指標を検索語に分解する。題名の一致だけで探さず、近い概念や旧来の呼び方、日本語・英語の表現を使う。例えばAIへの代行なら、delegation、human-agent interaction、mixed-initiativeなども候補になる。用語は問いに合うものを選ぶ。

論文の出版社・学会・大学の公開ページや論文本文を優先する。レビュー論文は周辺を知る入口とし、近い研究の一次資料へ進む。技術の現在の機能は公式ドキュメント・リリース情報・実装で確認する。ブログや過去の卒研はアイデアの入口で、既存研究全体の証明ではない。

候補を絞った段階では、最も近い研究を数件読み、次を対比する。件数を満たすために無関係な文献を付けない。

| 項目 | 確かめること |
| --- | --- |
| 既存研究の問い | 実際に何を調べていたか |
| 対象と条件 | 誰・どのデータ・どの場面か |
| 方法と評価 | 何と比べ、何を測ったか |
| 分かったこと | 結果として示された範囲はどこか |
| 候補との差 | 新たに問う条件・現象・仕組みは何か |
| 未確認部分 | 全文、関連分野、直近の研究など、まだ読めていない範囲 |

出典にはURL/DOI、読み取った内容、本文か要旨か、調査日を残す。検索結果の見出しだけを根拠にしない。論文で言及が見当たらない場合は「確認した範囲では扱われていない」と表現し、著者が未解決と述べたことと区別する。

新規性の状態は次のいずれか。

- `unverified`：未調査、読めない、資料が足りない。
- `search_scoped`：記録した範囲で関連資料を確認し、具体的な差を説明できる。新規性を保証する意味ではない。
- `teacher_reviewed`：教員の実際のコメントを得て記録した。学術上の新規性が確定した意味ではない。

検索できない場合は検索語と調査計画を作り、学生が渡した資料を読む。技術や論文を記憶だけで「確認済み」にしない。発見できなかった事実と、存在しないという断定を区別する。

## 新しい技術の確認

「新しく使える」を候補に添えるときは、以下を根拠と一緒に確認する。

- 能力：以前の方法と比べて、どんな操作・観察・体験が可能になるか。
- 時期：公開日、機能の提供開始日、確認日。記事の更新日を機能の公開日と混同しない。
- 利用可能性：アカウント、提供地域、アクセス権、必要な機器・実装。
- 実行条件：費用、制限、API/SDKやモデルのバージョン、データの扱い。
- 最小確認：学生の環境で試せる小さな操作と、失敗した場合の代替案。

既存の試作コードを読めたことと、学生環境で動作したことは別。モデルやプロトコル名だけで実行可能性を保証しない。Cloud Shellでできる部分と、ローカルの機器・ブラウザ等が必要な部分を分けて書く。

## 問いを評価につなぐ

問いの例：「条件が途中で変わる模擬購入課題で、AIへ渡す制約の表現形式は、制約違反率と確認の負担にどう影響するか」。具体化のための例であり、新規性は未確認。

テーマごとに次を決める。

1. **答えたい問い**：対象・変える条件・観察する結果。
2. **想定する説明**：仮説。探索研究なら、どんな現象を整理・発見したいか。
3. **比較・対照**：現在の方法、人による作業、機能を除いた版など、問いに意味のある基準。
4. **主要指標と定義**：何を1回の失敗・成功と数えるか。補助指標も必要に応じて。
5. **データ・協力者**：入手方法、対象範囲、実施条件。必要な相談や手続きがあれば具体的に記す。
6. **手順**：同じ課題をどう提示するか、順序効果・学習効果・難易度をどう扱うか。
7. **分析と限界**：ばらつき、繰り返し、少人数で言える範囲。人数や統計的有意性を根拠なく保証しない。
8. **再現条件**：モデル、プロンプト、設定、コードの版、課題セット、実施日。
9. **予備実験**：何を何件試し、どんな観察なら継続・修正するか。期間と費用を本人に合わせる。

性能・行動の研究では、成功率、意図からの逸脱、エラー、時間、介入回数などを検討する。ユーザー研究では、行動と説明、理解、選択の変化などを問いに合わせて組み合わせる。「便利だったか」だけで効果を結論付けない。技術比較では、モデルや入力条件を揃えられる範囲と、揃えられない範囲を明記する。

新しい問題を扱う研究は、必ずしも既存方式への優越性が主張ではない。失敗の分類、問題が起こる条件、適用の限界、評価方法の提案も貢献になり得る。開発するのは評価に必要な最小の仕組みから。

メディアアートでは、制作意図、既存作品との関係、新しい体験、作品の完成度を整理する。鑑賞者の記述・対話、観察、制作過程の批評などから方法を選ぶ。比較作品や機能を外した版が役立つ場合は使うが、対照実験を一律の必須条件にしない。

## 提案書の準備度を相談する

各軸を `ready` / `needs_work` / `unknown` で整理し、根拠や次の作業を添える。合計点や自動合否は作らない。

- `interest`：本人が選ぶ理由を説明している。
- `question`：何を明らかにするかが具体的。
- `novelty`：関連資料との具体的な差と、調査範囲が示されている。
- `evaluation`：問いに答える観察・比較・分析が計画されている。
- `feasibility`：期間、費用、技術、データ・協力者に見通しがある。
- `ownership`：本人が問いと方法を自分の言葉で説明している。

`ready` は教員に相談できる見通しを表す。新規性の確定、実験の承認、研究の成功を意味しない。
