# 発想を広げるときの切り口

## 学生の経験から始める

「興味がない」「分からない」という答えには、最近の生活で時間を使ったこと、誰かに説明したこと、面倒だったこと、面白かったことのいずれかを一つ聞く。専門用語や研究課題の答えを最初から要求しない。

推測は「こういう点に関心があるのかもしれません」と仮説として返す。経験そのものと、AIがそこから解釈した関心を混同しない。

## 組み合わせる

| 切り口 | 考えること | 問いの方向の例 |
| --- | --- | --- |
| 普遍性×時代性 | 以前からある欲求・不便を、最近使える能力がどう変えるか | 任せたいが納得もしたい → AI代行の確認方法 |
| 異業種×技術 | 学生の活動と、別の分野で使われる仕組みを結びつける | 推し活×権限委譲、地域活動×電子価値、創作×記憶するAI |
| 新しい能力→新しい問題 | 新しく可能になった行動が、誰のどんな困難を生むか | AIの外部操作 → 意図のずれ・誤実行・復帰の問題 |
| 条件をずらす | 既存研究が扱わなかった変化・制約・例外は何か | 条件が途中で変わる、データが欠ける、初心者が使う |
| 価値の衝突 | 両方望ましい目標が、どんな場面で両立しないか | 自動化と主体性、個人化と意外性、透明性と負担 |
| 表現を変える | 技術でどんな新しい感じ方・関わり方を作れるか | 鑑賞者の行為を引き継ぐ作品、電子価値を体験する表現 |

例は発想の種で、新規性を確認した研究テーマではない。同じ題材でも、条件・問い・観察の違う案を作る。すべてを「便利なアプリ」にまとめない。問いの変化がない技術名の置換は、別の案として数えない。

## 提案と反応の取り方

発想中の各案は短く、次の情報を添える。

- 本人のどの経験とつながるか。
- どんな意外な問題・体験を扱うか。
- 何を知りたいか。ここでは未完成の問いでよい。
- 小さく試すなら何をするか。
- まだ確かめていない新規性・技術・データの条件。

反応は「好きな案はどれですか」に加えて、その理由や引っかかる点を一つ聞く。全部違うなら、本人が嫌だと感じた方向を記録して組み合わせを変える。関心の強さをAIが推定した数値で順位付けしない。

## よくある出発点の育て方

- **「AIで旅行計画アプリを作る」**：旅行中の具体的な困り事を聞く。予定変更時の制約の引き継ぎ、本人の選択の理解など、観察できる問いを探す。単なる推薦精度の比較に固定しない。
- **「ブロックチェーンを使いたい」**：価値や権限を誰から誰へ渡す場面を聞く。ブロックチェーンが必要かも比較対象に含める。
- **「エージェントなら新しい」**：その能力が使える前後で、可能になった行動と生じた問題を具体化する。技術名や公開時期だけを新規性の根拠にしない。
- **「作品を作りたい」**：鑑賞者に起こしたい体験を聞く。有用性の質問に置き換えず、表現の仕組みとその違いを言葉にする。
- **「一つ選んでほしい」**：推薦はできるが理由・仮定・代替案を示し、本人の反応を待つ。既に本人が選んだテーマなら、改めて選ばせる手続きは省く。
